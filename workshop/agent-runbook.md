# Per-run operating procedure

Arena is the researcher, director, image generator and coding operator. These scripts are production utilities, not an independently operating AI engine.

1. **Inspect.** Check Git status/branch, existing outputs and source relationships. Inventory Node (22+), npm, FFmpeg/ffprobe, browser, disk and RAM. Don't delete unfamiliar files. Preserve earlier completed work unless explicitly superseded.
2. **Set up.** `npm ci`; read installed official HyperFrames skills. Attempt `npx hyperframes skills update`. Use the documented browser setup; use `runtime.mjs` only when the sandbox needs npm-provided binaries. Test real Kokoro synthesis, not merely voice listing. Use the explicit offline q8 workaround only if download is blocked. Record deviations. Never enable billing.
3. **Research.** Consider at least three distinct questions; compare curiosity, retention, plausibility/framing, evidence, visual potential, and short-form fit. Do not claim trends without evidence. Multiple credible references support important claims. For an impossible What If?, distinguish the impossible initial condition from real physical laws used afterward.
4. **Write.** Finish and verify the entire 110–135-word script first. Open within 2–3 seconds, explain consequences progressively, land a defensible twist. Omit greetings and branding. Write a numeric visual/sound specification before composing.
5. **Voice.** Select a clear male voice with `tts --list`. Put logical short phrases and adaptive speeds in `episode.json`. Delete/rebuild only identified stale derived takes when changing text. `voice.py` calls the official CLI and stores measured durations. Use pauses intentionally. If Kokoro fails, test free `edge-tts`; if that also fails, report the exact blocker rather than inventing narration.
6. **Images.** Call Arena's native image tool. Write one prompt per distinct image, compose vertically, leave caption room, use no embedded text, vary camera/scale while maintaining continuity. Save the prompts. Supplemental web media must have verified free usage terms and local copies.
7. **Sound.** Prefer an appropriate free licensed instrumental bed, with source/creator/license and a copy of required attribution. Reject unclear provenance. Use sparse licensed effects, automatic narration ducking, fades and measured loudness. Never declare a track CC0 just because an aggregator says so.
8. **Build.** Update the creative scene mappings in `build.py` for the topic; this is deliberate Arena art direction, not a fixed slideshow template. Use official registry components where they fit. Persist official source when adopting a recipe. Build editable sub-compositions and captions from the actual narration clock. Phrase captions are valid where no forced aligner exists; do not invent word timestamps or claim ASR. Individually generated short revelation words can provide real word boundaries.
9. **Inspect.** `npx hyperframes lint`; `check --safe-zone shorts --json`; `snapshot --review`. Inspect every scene midpoint and transitions at phone scale. Review warnings individually. Open the HyperFrames preview, expose it safely in Arena, but don't wait for approval when the user requested autonomous delivery.
10. **Render.** Explicit portrait root 1080×1920 / 30fps. `npx hyperframes render --quality delivery --fps 30 --workers 1 --no-browser-gpu --crf 20 -o ../output/final_video.mp4` from `film/`. Use more workers only with enough RAM. Keep only one delivery video; replace failed attempts at the same path.
11. **QA.** Run `qa.py` on the MP4, not source images. Check streams, 50–60-second length, complete decode, loudness/true peak, actual audio alignment, non-silent speech regions, black intervals and motion. Look at decoded opening, middle and ending frames. A numeric pass is not an auditory review; disclose that limitation. Fix and rerender failures.
12. **Package.** All nine mandatory output files: MP4, vertical JPG, script, SRT, YouTube description/title, scientific sources, asset ledger, storyboard, production report. Description must include legal credits, premise caveats and relevant references. No actual YouTube upload unless requested.
13. **Clean/deliver.** Use official `clean --dry-run` before `clean`. Remove identified test audio, temporary mix WAV and stale current-run captures after saving compact evidence. Do not delete HyperFrames project history. Verify files, run tests, inspect staged diff and sizes, commit/push current branch only, open a PR to the default branch without merging. Provide exact MP4 path and honest QA/engine/PR status.
